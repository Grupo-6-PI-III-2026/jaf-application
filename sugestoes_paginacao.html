Sugestões de Paginação

Projeto JAF - Backend (Spring Boot)

Por que implementar paginação?

A paginação é essencial para aplicações que lidam com grandes volumes de dados. Atualmente, o projeto JAF retorna todas as registros de uma vez, o que pode causar problemas de performance e usabilidade.

Performance

Reduz a carga no banco de dados e na rede, carregando apenas os dados necessários

Experiência do Usuário

Interface mais responsiva com carregamento progressivo de dados

Escalabilidade

Permite que a aplicação cresça sem degradação de performance

Redução de Custos

Menor consumo de memória e bandwidth no servidor e cliente

FuncionarioController - Listar Funcionários

FuncionarioController.java (linha 101-105)

Por que é importante:

  • Atualmente retorna TODOS os funcionários de uma vez
  • Em uma empresa com 1000+ funcionários, isso pode causar lentidão
  • Consumo excessivo de memória no servidor e no cliente
  • Sem filtro ou ordenação, dificulta encontrar funcionários específicos

        @RequestParam(defaultValue = "10") int size,
        @RequestParam(defaultValue = "nome") String sortBy,
        @RequestParam(defaultValue = "asc") String sortDir) {
    return ResponseEntity.ok(funcionarioService.listarPaginado(page, size, sortBy, sortDir));
}

FuncionarioService - Implementação da Paginação

FuncionarioService.java

Por que é importante:

  • Camada de serviço deve implementar a lógica de paginação
  • Usar Pageable do Spring Data para facilitar implementação
  • Permite ordenação dinâmica por diferentes campos
  • Retorna metadados (total de páginas, total de elementos) para o frontend
ANTES (Sem Paginação)
public List<FuncionarioListarDto> listarTodos() {
    List<Funcionario> funcionariosEncontrados = funcionarioRepository.findAll();
    return funcionariosEncontrados.stream().map(FuncionarioMapper::of).toList();
}
DEPOIS (Com Paginação)
public Page<FuncionarioListarDto> listarPaginado(int page, int size, String sortBy, String sortDir) {
    Sort sort = sortDir.equalsIgnoreCase("desc") ? Sort.by(sortBy).descending() : Sort.by(sortBy).ascending();
    Pageable pageable = PageRequest.of(page, size, sort);
    Page<Funcionario> funcionarios = funcionarioRepository.findAll(pageable);
    return funcionarios.map(FuncionarioMapper::of);
}

DEPOIS (DTO Customizado)
public class PaginatedResponseDto<T> {
    private List<T> data;
    private int currentPage;
    private int pageSize;
    private long totalElements;
    private int totalPages;
    private boolean hasNext;
    private boolean hasPrevious;
    
    // Construtor estático para converter Page
    public static <T> PaginatedResponseDto<T> of(Page<T> page) {
        PaginatedResponseDto<T> dto = new PaginatedResponseDto<>();
        dto.setData(page.getContent());
        dto.setCurrentPage(page.getNumber());
        dto.setPageSize(page.getSize());
        dto.setTotalElements(page.getTotalElements());
        dto.setTotalPages(page.getTotalPages());
        dto.setHasNext(page.hasNext());
        dto.setHasPrevious(page.hasPrevious());
        return dto;
    }
}

// NOVO: Handler para parâmetros de paginação inválidos
@ExceptionHandler(IllegalArgumentException.class)
public ResponseEntity<ErrorResponse> handleIllegalArgument(
        IllegalArgumentException ex) {
    ErrorResponse error = new ErrorResponse();
    error.setMessage("Parâmetro inválido: " + ex.getMessage());
    error.setStatus(HttpStatus.BAD_REQUEST.value());
    return ResponseEntity.status(HttpStatus.BAD_REQUEST).body(error);
}

// Adicionar validação no controller:
@GetMapping
public ResponseEntity<Page<FuncionarioListarDto>> listar(
        @RequestParam(defaultValue = "0") @Min(0) int page,
        @RequestParam(defaultValue = "10") @Min(1) @Max(100) int size,
        @RequestParam(defaultValue = "nome") String sortBy) {
    // Validar sortBy contra lista de campos permitidos
    if (!isValidSortField(sortBy)) {
        throw new IllegalArgumentException("Campo de ordenação inválido: " + sortBy);
    }
    return ResponseEntity.ok(funcionarioService.listarPaginado(page, size, sortBy));
}

Integração com Frontend

Exemplo de chamada API (React)

Por que é importante:

  • Frontend precisa adaptar para usar paginação
  • Implementar componentes de paginação (paginator)
  • Gerenciar estado de paginação
  • Implementar infinite scroll ou paginação tradicional
ANTES (Chamada simples)
// React - Antes
const fetchFuncionarios = async () => {
    const response = await api.get('/funcionarios');
    setFuncionarios(response.data);
};

// Renderiza todos de uma vez
{funcionarios.map(func => (
    <FuncionarioCard key={func.id} funcionario={func} />
))}
DEPOIS (Com paginação)
// React - Depois
const [page, setPage] = useState(0);
const [totalPages, setTotalPages] = useState(0);

const fetchFuncionarios = async (pageNum = 0) => {
    const response = await api.get('/funcionarios', {
        params: {
            page: pageNum,
            size: 10,
            sortBy: 'nome',
            sortDir: 'asc'
        }
    });
    setFuncionarios(response.data.data);
    setTotalPages(response.data.totalPages);
    setPage(response.data.currentPage);
};

// Componente de paginação
<Pagination>
    <Pagination.Prev onClick={() => fetchFuncionarios(page - 1)} disabled={page === 0} />
    <Pagination.Item active>{page + 1}</Pagination.Item>
    <Pagination.Next onClick={() => fetchFuncionarios(page + 1)} disabled={page === totalPages - 1} />
</Pagination>
